DAY 1 – PLAYWRIGHT LOCATORS (REAL-TIME + ADVANCED)
================================================================================

1. Strict Mode Violation
--------------------------------------------------------------------------------

Q: Why does Playwright throw Strict Mode Violation and how do you fix it in real
   projects?

A: • Playwright expects ONE unique element per locator
   • If multiple elements match → throws error

   Real Problem:
   page.locator('#button') // matches multiple elements

   Fix Approach:
   • Use role-based locator
   • Add exact text match
   • Handle dynamic elements like loaders

   Example:
   await expect(page.locator('.spinner')).toBeHidden();
   await page.getByRole('button', { name: 'Submit', exact: true }).click();

   Senior Insight: Locator should always represent user intention.


2. Locator Stability in Dynamic UI
--------------------------------------------------------------------------------

Q: How do you design stable locators in React/Angular apps?

A: • Avoid DOM-based XPath
   • Use:
     - getByRole()
     - getByLabel()
     - data-testid

   Why?
   • UI structure changes frequently
   • Attributes remain stable


3. Handling Multiple Matching Elements
--------------------------------------------------------------------------------

Q: Locator matches multiple elements. What will you do?

A: • Validate count:
   await locator.count();

   • Fix:
   locator.nth(0) OR refine locator with text/role


4. Relative XPath in Tables
--------------------------------------------------------------------------------

Q: How do you handle dynamic tables?

A: • Use text anchor → navigate relative

   XPath: //tr[td[text()='John']]//button[@class='edit']

   Why: IDs change, text remains stable


5. Locator inside iframe
--------------------------------------------------------------------------------

Q: Element inside iframe is not found. Why?

A: • Must switch context

   Example:
   page.frameLocator('#frame').getByText('Submit').click();

DAY 2 – ASSERTIONS & TYPESCRIPT FUNDAMENTALS
================================================================================

6. Web-First Assertion (Core Playwright Concept)
--------------------------------------------------------------------------------

Q: Why are Playwright assertions called "web-first"?

A: • They auto-retry until condition passes or timeout
   • Eliminates need for manual waits

   Example:
   await expect(locator).toBeVisible();

   Senior Insight: Assertions = synchronization tool


7. Hard vs Soft Assertion (Real Scenario)
--------------------------------------------------------------------------------

Q: When do you use soft assertions?

A: • Non-critical validations:
     - UI labels
     - Footer links

   Example:
   await expect.soft(locator).toHaveText('Welcome');

   Important:
   • Test continues execution
   • Failure reported at end


8. Assertion Timeout Strategy
--------------------------------------------------------------------------------

Q: Modal disappears after 6 sec but default timeout is 5 sec. What will you do?

A: • Override locally
   await expect(locator).toBeHidden({ timeout: 6000 });

   Avoid: Increasing global timeout


9. Static vs Retry Assertion
--------------------------------------------------------------------------------

Q: Difference between:
   expect(value)
   await expect(page).toHaveURL()

A: • expect(value) → no retry
   • toHaveURL() → retries

   Best Practice: Always use retry assertions for UI

DAY 3 – TYPESCRIPT TYPES & PARAMETERS
================================================================================

10. Why TypeScript in Playwright?
--------------------------------------------------------------------------------

Q: Why do we use TypeScript in automation?

A: • Type safety
   • Early error detection
   • Better IntelliSense
   • Improves maintainability


11. Typed Function Parameters
--------------------------------------------------------------------------------

Q: Why define types for function parameters?

A: function login(username: string, password: string)

   • Prevents invalid inputs
   • Improves readability
   • Avoids runtime errors


12. Optional Parameters
--------------------------------------------------------------------------------

Q: How do you handle optional parameters?

A: function search(value: string, filter?: string)

   • ? → optional
   • Used for flexible functions


13. Default Parameters
--------------------------------------------------------------------------------

Q: How do you define default values?

A: function login(role: string = 'user')


14. Return Type Importance
--------------------------------------------------------------------------------

Q: Why define return types?

A: function isValid(): boolean

   • Ensures consistent output
   • Avoids unexpected behavior


15. Real Framework Question
--------------------------------------------------------------------------------

Q: How do you design reusable utility functions with types?

A: async function clickElement(locator: Locator): Promise<void> {
      await locator.click();
   }

   Benefits:
   • Reusability
   • Type safety
   • Framework scalability

DAY 4 – ALERTS (REAL-TIME HANDLING)
================================================================================

16. Handling Alerts
--------------------------------------------------------------------------------

Q: How do you handle alerts in Playwright?

A: page.on('dialog', async dialog => {
      console.log(dialog.message());
      await dialog.accept();
   });


17. Types of Alerts
--------------------------------------------------------------------------------

Q: Different alert types and handling?

A: • Alert → accept()
   • Confirm → accept() / dismiss()
   • Prompt → accept('value')


18. Alert Not Appearing Issue
--------------------------------------------------------------------------------

Q: Alert not getting handled. Why?

A: • Listener not registered before action

   Fix:
   page.on('dialog', async dialog => {
     await dialog.accept();
   });
   await page.click('#trigger');


19. Handling Prompt Input
--------------------------------------------------------------------------------

Q: How to pass value in prompt?

A: await dialog.accept('TestUser');


20. Real-Time Alert Debug Scenario
--------------------------------------------------------------------------------

Q: Test fails due to unexpected alert. What will you do?

A: • Add global listener
   • Log alert message
   • Handle gracefully

   Example:
   page.on('dialog', async d => {
     console.log(d.message());
     await d.dismiss();
   });
